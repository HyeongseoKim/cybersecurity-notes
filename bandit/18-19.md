# Bandit — Level 18 → 19

- **Date:** 2026-09-14
- **Time spent:** about 15 minutes
- **Note:** Written right after solving.

## The goal, in my own words

The password was in a file called `readme` in the home directory. The problem was
that someone had changed `.bashrc` so that logging in with SSH threw me straight
back out. I had to read the file without getting a shell.

## What I tried first

I logged in the normal way, the same as every level before:

```bash
ssh bandit18@bandit.labs.overthewire.org -p 2220
```

The password was accepted and the welcome banner appeared, but then:

```
Byebye !
Connection to bandit.labs.overthewire.org closed.
```

So the login itself worked. It was the shell that closed immediately.

## Where I got stuck


Two things slowed me down.

First, I did not know that `ssh` can take a command after the destination. It
took me a few minutes to find it in the manual, because I was looking for it in
the list of options — I thought `command` was an option name. It is not an
option, so it is not in that list. It just means any command I want to run on
the server, and it is explained in the DESCRIPTION section instead.

Second, after I understood the `command` part, I used the wrong file name. My own
repository on my Mac has a file called `README.md`, so I typed that. The Bandit
server answered:

    cat: README.md: No such file or directory

The file on the server is called `readme`. I had taken the name from my own
laptop instead of from the server.

## What actually worked

`ssh` does not only open a shell. If I put a command after the destination, it
logs in, runs that command, sends back the output, and disconnects. The shell is
only what I get when I do not give a command.

First I listed the directory to see what was there:

```bash
ssh bandit18@bandit.labs.overthewire.org -p 2220 ls -la
```

```
-rw-r--r--  1 root      root      220 Feb 13  2026 .bash_logout
-rw-r-----  1 bandit19  bandit18 3874 Jun 24 14:59 .bashrc
-rw-r--r--  1 root      root      807 Feb 13  2026 .profile
-rw-r-----  1 bandit19  bandit18   33 Jun 24 14:59 readme
```

This output already showed which file had been changed. `.bash_logout` and
`.profile` are owned by `root` and dated February, which is when the account was
created. `.bashrc` is owned by `bandit19` and dated June 24, so it is the odd one
out. Comparing owners and timestamps is enough to point at the modified file.

`.bashrc` and `readme` are both `-rw-r-----` with group `bandit18`, so I could
read them as a group member.

```bash
ssh bandit18@bandit.labs.overthewire.org -p 2220 cat .bashrc
```

Almost all of it is the standard Debian `.bashrc`. Only the last two lines were
added:

```bash
echo 'Byebye !'
exit 0
```

Then I read the file I actually needed:

```bash
ssh bandit18@bandit.labs.overthewire.org -p 2220 cat readme
```

## Why my method got past the .bashrc


My command was not interactive, because it ran one command instead of opening a
prompt. Near the top of `.bashrc` there is a check that calls `return` when the
shell is not interactive, so bash stops reading the file there. The `exit 0` at
the bottom is never reached, which is why my command could run.

## New to me

| Command / concept | What it does | Where else I'd use it |
|---|---|---|
| `ssh <host> <command>` | Logs in, runs one command there, and disconnects, without opening a shell | Any time a shell is blocked, or for scripts that run one command on a server |
| reading owners and timestamps in `ls -la` | The file whose owner or date does not match the others is the one that was changed | Checking whether a system has been tampered with |
| `exit 0` | Ends the shell and reports success. `0` means success, anything else means an error | |
| `$?` | Holds the exit status of the last command | |
| `.bashrc` vs `.bash_logout` | `.bashrc` runs when a shell starts, `.bash_logout` runs when it ends | |

## One thing I still don't fully understand

If the person who set up this level had put `exit 0` above the interactive check
instead of at the bottom, my method would not have worked. I do not know how I
would read the file in that case.
