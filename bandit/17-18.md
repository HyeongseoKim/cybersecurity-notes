# Bandit — Level 17 → 18

- **Date:** 2026-09-11
- **Time spent:** about 10 minutes
- **Note:** Written right after solving.

## The goal, in my own words

This level gave me two files, `passwords.old` and `passwords.new`. Only one line
was different between them, and that line was the password for the next level.

## What I tried first

I checked the size of the two files first, and then counted the lines:

```bash
wc -l passwords.old passwords.new
```

Both files had 100 lines. Comparing 100 lines by eye would be slow and easy to
get wrong, so I looked for a command that compares two files. I did not know its
name, so I searched the manual pages by keyword:

```bash
man -k compare
```

`diff` came up in the list.

## Where I got stuck

I did not really get stuck on this level. The only part I did not understand at
first was the output format. I could see that `57c57` meant something about line
57, but I did not know what the letter `c` meant. It stands for "changed", and
`a` and `d` are used for added and deleted lines.

## What actually worked

```bash
diff passwords.old passwords.new
```

The output marks each differing line with `<` or `>`. `<` is the line from the
first file I passed, and `>` is the line from the second file. I passed
`passwords.old` first and `passwords.new` second, so the line I needed was the
`>` one, because the next level's password is in the newer file.

If I had passed the files in the other order, the answer would have been the `<`
line instead. Knowing the command was not enough by itself — I also had to know
which side of the output belonged to which file.

## New to me

| Command / concept | What it does | Where else I'd use it |
|---|---|---|
| `man -k` (also `apropos`) | Searches manual page descriptions by keyword, for when I know what I want to do but not the command name | Later Bandit levels, picoCTF, and any server with no internet access |
| `diff` | Compares two files and shows only the lines that differ | |
| `<` and `>` in diff output | `<` is the first file, `>` is the second, so the order of the arguments decides which side holds the answer | |
| `wc -l` | Counts lines in a file, and prints the file name next to the count | |
| `c`, `a`, `d` in diff output | changed / added / deleted — the letter says what kind of difference it is | |

## One thing I still don't fully understand

`diff` found the one different line out of 100. I do not know how it does this.
It cannot be a simple line-by-line comparison, because if a line were added in
the middle, everything after it would look different — but `diff` reports that
correctly as one added line.

## Compared to level 16 → 17

This level was much easier, and I think there are two reasons.

The level itself was simpler: the two files were already in front of me, it took
only one step, and nothing failed along the way. In level 16 → 17 I only got a
range of port numbers, and I had to work out what to do before I could start.

But I was also better prepared. Instead of guessing, I used `man -k` to find the
command I needed. That is a habit I did not have two days ago.
